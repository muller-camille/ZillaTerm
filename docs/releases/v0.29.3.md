**Sessions PSM Windows : les disques de ce poste arrivent sur la cible**, comme avec la case « Map local drives » du PVWA.

## Corrigé en 0.29.3

- L'option « Partager les disques de ce poste avec les sessions PSM Windows » (Paramètres › CyberArk, cochée par défaut) **demande maintenant les disques au PVWA**, comme la case « Map local drives » de sa fenêtre de connexion (paramètre `AllowMappingLocalDrives`). Si le composant de connexion le permet, le PVWA les écrit dans le fichier RDP signé et le serveur PSM les transmet à la cible : ils apparaissent dans Explorateur › Ce PC, dans l'onglet comme dans la Connexion Bureau à distance.
- En 0.29.2, ZillaTerm partageait les disques avec le seul serveur PSM, sans les demander au PVWA : le PSM ne les transmettait pas à la cible. Ce partage côté poste est retiré (il exposait les disques au serveur PSM sans rien apporter).
- Si un composant refuse le paramètre, la connexion est redemandée sans lui (noté au journal de débogage) : elle n'est jamais bloquée par les disques.
- Le journal de débogage indique si les disques du poste ont été demandés ; le fichier RDP est lu aussi quand il demande `*;DynamicDrives` ou l'ancienne clé `redirectdrives:i:1`.
