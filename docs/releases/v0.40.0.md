**Sessions PSM Windows : ne partager que les dossiers choisis du poste plutôt que tous ses disques, réglable par l'équipe. Client Bureau à distance mis à jour vers FreeRDP 3.32.2 (version de sécurité). Paramètres ouverts d'un clic, avec une page À propos ; bouton « Reconnecter » dans les onglets Bureau à distance.**

## Nouveau en 0.40.0

### Bureau à distance

- **Disques du poste partagés** (Paramètres › Bureau à distance) : **Aucun**, **Tous les disques** (comme avant, par défaut) ou **Ces dossiers seulement**. La case « Partager les disques de ce poste » devient ce choix ; les réglages existants sont repris (case cochée : Tous les disques ; décochée : Aucun).
- **Ces dossiers seulement** : une liste de dossiers, chacun avec le nom vu dans la session (`\\tsclient\Nom`) et son chemin sur le poste, complet (`C:\…`, `\\serveur\partage\…`) ou commençant par une variable (`%USERPROFILE%\Partage`, remplacée à chaque connexion, pour qu'un même réglage serve sur chaque poste). « Ajouter un dossier… » propose le nom d'après le dossier choisi.
  - Sessions dans un onglet avec le client de ZillaTerm : seuls ces dossiers sont partagés (option `/drive:Nom,Chemin` du client FreeRDP, à la place de tous les disques), si le composant de connexion du PVWA permet les disques.
  - Dossier absent à la connexion (clé USB retirée, partage injoignable) : non partagé, et la barre d'état le dit.
  - Connexion Bureau à distance et le contrôle Bureau à distance de Windows ne savent partager que des disques entiers : dans ce mode, aucun disque pour eux plutôt que tous. Pour Connexion Bureau à distance, ZillaTerm demande au PVWA un fichier sans disques, y compris quand l'onglet passe la main à Connexion Bureau à distance.
- **Fichier d'environnement de l'équipe** : le choix (`PsmShareFoldersOnly`) et la liste (`PsmSharedFolders`) peuvent y être diffusés, avec la pastille « Équipe ». Un dossier sur un partage réseau est signalé à l'import, avec le serveur.
- Moins de disques partagés, c'est aussi moins de demandes du serveur à des disques inutiles (lecteurs réseau qui répondent mal).
- **FreeRDP 3.32.2** pour les sessions PSM affichées dans un onglet et les connexions directes : release `wfreerdp-3.32.2-1` du fork, avec les mêmes correctifs génériques qu'avant (branche `patches-3.32.2`), reportés sans changement.
- **Fin de la boucle « Error code not found: 87 »** sur les disques partagés : FreeRDP 3.32.1 signalait au serveur chaque fermeture de fichier comme un échec dès qu'une erreur Windows était survenue avant sur ce disque (il renvoyait la dernière erreur, même après une fermeture réussie). Le journal de débogage se remplissait alors de `drive_map_windows_err: Error code not found: 87`, en boucle sur un fil par disque partagé. Corrigé dans FreeRDP 3.32.2 : une fermeture réussie est signalée comme telle.

### Interface

- **Paramètres** : le bouton de la barre ouvre directement la fenêtre, sans menu. Nouvelle page **À propos** (version, liens, licence, dossier des paramètres, recherche d'une nouvelle version et téléchargement vérifié), avec la case « Rechercher une nouvelle version au démarrage » ; le lien de nouvelle version de la barre d'état ouvre cette page. « Afficher le fichier du journal » est juste sous la case « Journal de débogage » (page Général). L'import des sessions d'un autre logiciel reste dans le menu « Importer » de « Mes serveurs ».
- **Sessions Bureau à distance dans un onglet** : bouton « Reconnecter » dans la barre de l'onglet, à côté de « Plein écran » et « Déconnecter » (comme « Reconnecter » du menu de l'onglet : nouvelle demande au PVWA pour une session PSM, confirmation si la session est ouverte).

### Journal de débogage

- **Disques du poste partagés** : avec le journal de débogage et des disques ou dossiers partagés, chaque demande du PSM aux disques (disque, opération) et sa réponse (code NTSTATUS) sont écrites dans le journal (lignes `rdpdr`), pour comprendre un disque qui ne répond pas ou une erreur en boucle. Jamais le nom ni le contenu d'un fichier. Bavard (deux lignes par demande) : à désactiver une fois le problème reproduit.

## Sécurité

- FreeRDP 3.32.2 est une version de sécurité : 45 avis publiés par le projet FreeRDP, et un code durci contre les messages d'un serveur ou d'un client malveillant (passerelle, presse-papiers, cartes à puce, codecs d'image, images). Le client est vérifié comme les précédents : somme SHA-256 figée et attestation de provenance de GitHub. OpenSSL reste en 3.5.9, dernière version de la branche 3.5.
- Moindre privilège : les programmes de la session PSM ne voient que les dossiers choisis, plus tout le poste.
- Jamais plus que demandé : un dossier n'est partagé que si le fichier du PVWA permet les disques ; un mode qui ne peut pas être respecté (Connexion Bureau à distance, contrôle de Windows) ne partage rien.
- Noms et chemins vérifiés avant d'être passés au client FreeRDP : pas de « , » ni de guillemet, jamais un chemin relatif, un chemin de périphérique (`\\?\`, `\\.\`) ni « * » (tous les disques). Un fichier d'environnement avec un dossier invalide est refusé.

## Compatibilité

- Réglages existants repris tels quels (Tous les disques ou Aucun). Une version plus ancienne ignore le choix et la liste d'un fichier d'environnement : elle partage tous les disques si le partage des disques y est activé.
- Le certificat épinglé du serveur reste vérifié avant tout le reste (`/cert:deny` et empreinte), avec FreeRDP 3.32.2 comme avant.
